### 🔴 КРИТИЧЕСКАЯ ПРОБЛЕМА #1: Утечка частично загруженных workbooks

**Файл:** `utils/clean_excel.py`
**Строки:** 78-91
**Серьезность:** КРИТИЧЕСКАЯ

**Описание проблемы:**
```python
# БЫЛО (строки 78-91):
try:
    wb_data = load_workbook(input_file, data_only=True)  # может загрузиться
    wb_format = load_workbook(input_file)  # может exception - wb_data останется открытым!
    use_openpyxl = True
except Exception as e:
    use_openpyxl = False

if not use_openpyxl:
    return clean_excel_pandas(input_file, output_file)  # ❌ wb_data НЕ ЗАКРЫТ!
```

**Сценарий утечки:**
1. `wb_data` успешно загружается (строка 80)
2. Exception на `wb_format` (строка 82)
3. Выполняется except блок, `use_openpyxl = False`
4. Функция делает early return через pandas (строка 91)
5. `wb_data` остается открытым в памяти! 💥

**Исправление (коммит 59d4b87):**
```python
try:
    wb_data = load_workbook(input_file, data_only=True)
    wb_format = load_workbook(input_file)
    use_openpyxl = True
except Exception as e:
    use_openpyxl = False

    # ✅ ДОБАВЛЕНО: Закрываем частично загруженные workbooks
    if wb_data:
        try:
            wb_data.close()
        except Exception:
            pass
        wb_data = None

    if wb_format:
        try:
            wb_format.close()
        except Exception:
            pass
        wb_format = None

if not use_openpyxl:
    return clean_excel_pandas(input_file, output_file)  # ✅ Теперь безопасно
```

**Влияние:**
- Предотвращена утечка памяти в edge case сценариях
- Особенно критично при batch обработке файлов
